# Stage 2: The State Engine

**Goal:** Build a state machine that keeps track of the conversation thread and manages "Memory."

## Conceptual Grounding

An LLM API is **stateless**. It has no memory of the question you asked five seconds ago. To create the illusion of a continuous conversation (or an agent track), your application must maintain an append-only array of all historical messages and send the entire history back to the API with every new transaction.

## The State Machine

```
+---------------------------------------------------------------------------------+
|                                 THE STATE ENGINE                                |
|                                                                                 |
|  [User Prompt] ──────────┐                                                      |
|                          ▼                                                      |
|   History Array: [ {role: "user", parts: [...]}, {role: "model", ...} ]         |
|                          ▲                                                      |
|  [API Response] ─────────┘                                                      |
+---------------------------------------------------------------------------------+
```

## Message Roles

An agent's state engine must explicitly track the following roles:

- **`user`**: Inputs sent by the human developer
- **`model`**: Raw outputs, chain-of-thought, and action requests generated by the model
- **`function`** or **`tool`**: The execution outputs generated by your sandbox environment and passed back to the model as observations
